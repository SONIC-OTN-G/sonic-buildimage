# ARM64 iSulad 离线修复包：20261106-r1

本版保留“私有用户态 rootfs + chroot + 独立挂载/网络命名空间”的部署方式。
iSulad 仍是 openEuler 官方 2.1.5 二进制；runc 1.5.2 已从源码打补丁并重编译为 ARM64 静态程序。
目标设备不用安装 Python、yum、sudo 或 sha256sum；程序及共享库已在包内。以 root 运行。

## 部署与回滚

先在旧包目录运行 `sh control.sh stop`。保留旧目录，不覆盖它，也不要直接复制旧 data/ 到新包。
在可执行、可写且支持 Linux 权限的磁盘上新建目录（例如 `/ofs1/isulad-fix-20261106`），上传压缩包与随附 busybox-arm64。

```sh
cd /ofs1/isulad-fix-20261106
chmod 755 busybox-arm64
./busybox-arm64 xz -dc isulad-offline-arm64-fix-20261106-r1.tar.xz | ./busybox-arm64 tar -xf -
cd isulad-offline-arm64
sh verify.sh
sh control.sh check
sh control.sh start
sh control.sh status
sh test.sh smoke
```

`verify.sh` 使用包内 BusyBox，不依赖设备的 sha256sum。只对初次解压的原始文件做校验；运行后有状态文件变化。
通过 `sh 脚本` 可避免脚本自身没有执行位的问题；若分区整体 noexec，必须把程序放到允许执行的分区，chmod 无法绕过挂载限制。

如启动提示 OverlayFS 不可用，先确认是否已加载厂商提供的匹配模块。只有需要加载时才执行：

```sh
sh scripts/load-overlay.sh /绝对路径/overlay.ko
sh control.sh start
```

此辅助命令会加载宿主内核模块。包不包含、不自动下载、不强行加载任意 overlay.ko；内核版本、配置和符号必须匹配，模块依赖也必须满足。

## 三个业务镜像

把已有三个 `docker-*-standalone-arm64.tar.gz` 直接放进新包 `inbox/`，不用手动解压，不需重建业务镜像。

```sh
sh test.sh load-sonic
sh test.sh database
sh test.sh ot
sh isula ps -a
```

smoke 会比较 exec 与容器主进程的根目录和 mount namespace，检查 `/proc/$$`，并在重启后重复检查。
database 验证 ARM64、Redis PING/SET/GET、swsscommon 导入和表读写、socket 绑定、停止/启动。
ot 验证 OTSS 与 syncd 的独立入口、依赖库、真实业务二进制帮助入口、exec、绑定目录和重启；不代表设备硬件业务主循环或容器间通信已经验证。
测试结束的容器通常保留但停止，需用 `ps -a` 查看。交互进入一个正在运行的业务容器：

```sh
sh isula exec -it 容器名称 /bin/sh
```

## 日志与失败信息

```sh
sh control.sh collect
./bin/busybox tail -n 60 logs/start.log
./bin/busybox tail -n 80 evidence/isulad.log
```

`diagnostics.tar.gz` 包含日志和 evidence。不能发送整个文件时，提供失败命令、原始错误、对应测试目录 test.log 的最后几十行。
smoke 日志在 `evidence/offline-smoke-*/test.log`，database 在 `evidence/results-*/test.log`，OT 在 `evidence/results-ot-*/test.log`。
本版业务测试直接写日志文件，避免精简设备没有 `/dev/fd` 时 Bash 进程替换失败。

停止与回滚：

```sh
sh control.sh stop
# 回到保留的旧包目录后：
# sh control.sh start
```

不要同时运行旧、新两个引擎；停止后再移动/清理解压目录。此包不替换设备 libc，不安装系统服务，不替换设备内核。

## 修复内容及代码位置

1. `runc` 的 `libcontainer/process_linux.go`、`libcontainer/nsenter/nsexec.c`：exec 切换命名空间前固定主进程 root，核验进程存活/启动时间；切换后、降权前恢复 root/cwd，并关闭描述符。失败终止，不在错误根目录执行；修复启动前错误时日志管道清理。
2. `scripts/ns-start.sh`：保留实际共挂载控制器组合，例如一个 `cpu,cpuacct` 挂载配合 cpu/cpuacct 相对软链接；不卸载/改名设备的原挂载。
3. `scripts/ns-start.sh`：内核启用但未挂载的 devices 在私有命名空间内补挂载；不可用就明确失败。可选且不可作为 v1 挂载的控制器告警跳过。
4. `rootfs/usr/bin/runc`：仅向真正的 create/run 子命令添加 `--no-pivot`，处理初始 rootfs 上 pivot_root(EINVAL)；exec 参数中出现 run/create 不会被误改。
5. 同一包装层保留 `/dev/shm` bind 的无效 size= 选项兼容修复，真正的 tmpfs 大小仍由 iSulad 配置。
6. `control.sh`：启动前验证 OverlayFS；初始化 data/isulad_tmpdir 为 root:root、0700，创建 evidence 目录。
7. `scripts/load-overlay.sh`：提供显式、可见错误的匹配模块加载入口；它不是让没有 OverlayFS 的内核凭空获得支持。
8. `rootfs/tests/smoke.sh`：增加 exec 根目录/命名空间/proc 一致性和重启回归。
9. 两个业务测试脚本：移除依赖 `/dev/fd` 的 Bash 日志进程替换。
10. `control.sh collect`：显式调用包内 BusyBox tar/gzip 并检查退出状态；设备没有 gzip 时仍可生成有效诊断包。
11. `verify.sh` 与重新生成的 SHA256SUMS：解决目标机缺 sha256sum 及修改脚本后旧校验清单失效的问题，不关闭完整性检查。

各特殊适配处均有 SONIC-OFFLINE / Vendor fix 注释说明原因。源代码、补丁、构建脚本在单独的 source 压缩包中。

## 边界

cgroup 挂载可见性隔离在私有命名空间内，但控制器层级分配和实际资源限制仍是共享内核状态；不是另一套内核。
根目录恢复补丁是本项目的适配补丁，不宣称是上游正式发布版本，也不扩大 exec 用户的权限。
本地虚拟机不是厂商固件；目标设备仍需按上面的 smoke/database/ot 顺序验收。
空间需求仍由镜像解压层、容器可写层、日志决定；建议新测试目录至少留约 2 GiB 可用空间，旧包并存和长期数据需另计。
