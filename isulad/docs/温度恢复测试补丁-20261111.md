# 温度恢复时序测试补丁（2026-11-11）

适用于 otn-system-arm64-preview-20261110.tar.gz。只更新 test_pmon.py 和 test_north.py，不更换镜像、守护进程或配置数据。

修复内容：pmon 测试降温后等待 STATE_DB 中 TEMP 1 温度恢复；测试结束恢复原始输入后也等待对应上报。SNMP 测试不再写死 3500，要求虚拟输入、STATE_DB、SNMP 三者一致，并校验传感器状态为有效；最多等待 120 秒，超时打印实际值。此测试期间不要并发修改虚拟温度。

安装：不要与正在运行的 system.sh test 并发覆盖脚本。将本目录中的两个 .py 文件上传设备临时目录（以下假设 /tmp/otn-test-fix/），再在设备宿主执行：

```sh
ENGINE=/你的实际路径/isulad软件包目录
PKG="$ENGINE/evidence/otn-system"
BB="$ENGINE/bin/busybox"

# 只首次创建备份，保留原始版本
test -f "$PKG/test_pmon.py.before-temp-fix" || "$BB" cp "$PKG/test_pmon.py" "$PKG/test_pmon.py.before-temp-fix"
test -f "$PKG/test_north.py.before-temp-fix" || "$BB" cp "$PKG/test_north.py" "$PKG/test_north.py.before-temp-fix"
"$BB" cp /tmp/otn-test-fix/test_pmon.py "$PKG/test_pmon.py"
"$BB" cp /tmp/otn-test-fix/test_north.py "$PKG/test_north.py"

sh "$PKG/system.sh" test
```

容器的 /system 是安装目录的只读 bind mount，在设备宿主更新文件即可；每次 exec 都重新运行测试脚本，不需要重启容器。不要在容器内覆盖 /system，也不要删除 SNMP 断言来绕过测试。

额外等待会让整套测试变长，通常增加至多一个温度上报周期；出现真实采集异常时仍会超时失败。
旧全量压缩包保留不变，因此新安装旧包后同样需要应用这个补丁。原包的 SHA256-MANIFEST.json 记录原始文件摘要，覆盖后这两个文件与原摘要不同是预期现象；补丁自身的 SHA256SUMS 用于校验更新的两份脚本。
